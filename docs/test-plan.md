# Test plan

Date: 2026-10-17
Scope: macos/ (Swift package, test targets MadeCoreTests and MadeAppTests)
Audit run: 20261017-112015

The plan covers 193 capabilities. Package.swift declares two test targets, MadeCoreTests (line 51) and MadeAppTests (line 56). MadeCoreTests holds 70 Swift files, one of which (KernelTestSupport.swift) is a shared support file. MadeAppTests holds 17 Swift files. The two targets hold 1,160 tests, 957 in MadeCoreTests and 203 in MadeAppTests. Every file except StdioProcessTests.swift imports MadeCore or MadeApp, and StdioProcessTests.swift launches the built executable instead. The audit did not run `swift test`, so pass and fail status is unobserved.

Of the 193 capabilities, 174 have at least one unit or integration reference. The other 19 have none. Eight of those are removed or claimed-only rows (UI-1, UI-11, UI-12, UI-13, UI-18, VIEW-17, UI-23, AGENT-26), which need no test until built. Seven are the Copilot rows AGENT-10 to AGENT-16, which have had no caller since #124. Four are reachable capabilities with no test: INPUT-13, UI-36, UI-37, and DSL-15.

UI-33 has one reference that asserts nothing about clearing the console log, so Table 2 lists it and records the gap. The plan cites 1,150 of the 1,151 tests, and DocumentModelTests.testExtendedDocumentProperties is cited by no capability. The audit matched test names to capabilities by the entry points and wording in the capability set, so a test that exercises a capability without naming it may be missing.

ADR-D10 establishes the layered UI and viewport testing strategy. Initial harness implementation is tracked under QA-UITEST-01 (#550) and offscreen goldens under BL-QA-06 (#321). Table 2 records UI E2E as none for the 118 capabilities with a UI layer and as n/a for the others until the harness lands. Table 3 summarizes that gap in one row, and the plan raises no per-capability finding for it.

Gating note: the suite gates 83 tests with `.enabled(if: MetalTestSupport.isMetal4Available)` and 2 tests with `MTLCreateSystemDefaultDevice() != nil`. Table 2 marks them [M4] and [GPU]. They skip on hosted CI runners, where the paravirtual GPU lacks Metal 4, so they run only on a local Apple-silicon machine. StdioProcessTests skips when the MadeApp executable is not built and is marked [BIN]. No test uses `.disabled` or `withKnownIssue`. Under ADR-D10, Layer 2 offscreen goldens skip on hosted CI, while Layer 3 and 4 viewport tests require local execution via `make test-viewport` with pre-push pass-record verification.

KernelClientTests.testRapidRequestsConflateToLatestValue was flaky and exposed a race in KernelClient.executePending (DSN-efe60d18). Issue #90 fixed both, and testStaleDebounceDoesNotStrandNewerRequest covers the race.
