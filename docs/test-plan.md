# Test plan

Date: 2026-10-17
Scope: macos/ (Swift package, test targets MadeCoreTests and MadeAppTests)
Audit run: 20261017-112015

The plan covers 190 capabilities. Package.swift declares two test targets, MadeCoreTests (line 51) and MadeAppTests (line 56). MadeCoreTests holds 69 Swift files, one of which (KernelTestSupport.swift) is a shared support file. MadeAppTests holds 16 Swift files. The two targets hold 1,151 tests, 951 in MadeCoreTests and 200 in MadeAppTests. Every file except StdioProcessTests.swift imports MadeCore or MadeApp, and StdioProcessTests.swift launches the built executable instead. The audit did not run `swift test`, so pass and fail status is unobserved.

Of the 190 capabilities, 168 have at least one unit or integration reference. The other 22 have none. Nine of those are removed or claimed-only rows (UI-1, UI-11, UI-12, UI-13, UI-18, VIEW-17, INPUT-11, UI-23, AGENT-26), which need no test until built. Seven are the Copilot rows AGENT-10 to AGENT-16, which have had no caller since #124. Two are partial rows, VIEW-2 and DSL-11. Four are reachable capabilities with no test: INPUT-13, UI-36, UI-37, and DSL-15.

UI-33 has one reference that asserts nothing about clearing the console log, so Table 2 lists it and records the gap. The plan cites 1,150 of the 1,151 tests, and DocumentModelTests.testExtendedDocumentProperties is cited by no capability. The audit matched test names to capabilities by the entry points and wording in the capability set, so a test that exercises a capability without naming it may be missing.

No XCUITest target exists. The user directed a shift to XCUITest, and ADR-D10 with issue QA-UITEST-01 proposes the harness. Table 2 therefore records UI E2E as none for the 117 capabilities with a UI layer and as n/a for the others. Table 3 summarizes that gap in one row, and the plan raises no per-capability finding for it.

Gating note: the suite gates 83 tests with `.enabled(if: MetalTestSupport.isMetal4Available)` and 2 tests with `MTLCreateSystemDefaultDevice() != nil`. Table 2 marks them [M4] and [GPU]. They skip on hosted CI runners, where the paravirtual GPU lacks Metal 4, so they run only on a local Apple-silicon machine. StdioProcessTests skips when the MadeApp executable is not built and is marked [BIN]. No test uses `.disabled` or `withKnownIssue`.

KernelClientTests.testRapidRequestsConflateToLatestValue was flaky and exposed a race in KernelClient.executePending (DSN-efe60d18). Issue #90 fixed both, and testStaleDebounceDoesNotStrandNewerRequest covers the race.

Table 1 gives the class decisions. Table 2 gives the per-capability coverage. Table 3 gives the UI end-to-end summary. In Table 2, a cell names the test file and then its test functions. A cell with more than 10 matches shows the first five and a count. "All N tests" means every test in the file.
