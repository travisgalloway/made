# ADR-D3: Topological Naming Strategy

- **Status:** Accepted, 2026-10-14
- **Issue:** #144
- **Implemented by:** #152 (BL-KRN-04), #170 (BL-FND-02), #153 (BL-AGT-05), #420 (Swift B-rep core), #82, #35, #36, #41, #189, #202, #203, #205, #214, #294, #295, #296, #332, #333, #360

## Context

In a parametric, history-based mechanical CAD modeling system ([ADR-D2](./ADR-D2-modeling-paradigm-and-document-model.md), #143), downstream features reference topological sub-elements (faces, edges, vertices) produced by upstream features. For instance:
- A 2D sketch plane references an extruded planar face (#36).
- A fillet feature applies round blends along specific solid edges (#35, #82).
- A draft feature angles selected planar or cylindrical faces (#296).
- A shell feature hollows a body through open faces (#294).
- Direct editing operations translate, offset, or delete individual faces (#41, #203).
- 2D engineering drawings project silhouette edges and dimensions linked to specific model elements (#189, #332).
- CAE meshing anchors boundary constraints and surface loads to specific faces and edges (#205, #214, #360).

When upstream parameters change, the geometry kernel recomputes the boundary representation (B-rep). Because modern geometry kernels (including OpenCASCADE Technology, [ADR-D1](./ADR-D1-canonical-geometry-kernel.md)) re-instantiate fresh C++ topology objects and transient pointers across re-evaluations, storing raw integer indices (such as "face #4" or "edge #12") or internal memory addresses leads to catastrophic failures: downstream features attach to the wrong geometric elements, blend operations self-intersect or fail, or the kernel crashes. This is the classic "topological naming problem" in computer-aided design.

`made` requires a persistent, deterministic sub-element naming strategy that uniquely identifies, tracks, and persists topological sub-elements across parametric regeneration, direct edits, and `.made` document package serialization ([ADR-D7](./ADR-D7-made-encoding.md), #83).

## Options Considered

1. **OCCT OCAF `TNaming` (`TNaming_NamedShape`).** Rejected.
   OpenCASCADE's Open CASCADE Application Framework (OCAF) includes a dedicated topological naming subsystem based on `TNaming_NamedShape` attributes attached to an OCAF data tree (`TDF_Data`).
   While feature-complete within the OCCT ecosystem, OCAF imposes its own monolithic document architecture (`TDocStd_Document`), transactional undo/redo manager, and proprietary binary storage format. Adopting OCAF would directly compete with and duplicate Swift's `ReferenceFileDocument`, system `UndoManager` (#39), and the `.made` bundle architecture (ADR-D7, #83, #376).
   Furthermore, OCAF types cannot cross into `MadeCore` without leaking C++ implementation details past the engine-neutral wire boundary mandated by Invariant 4.

2. **Pure Geometric Signature Matching.** Rejected.
   Relying exclusively on geometric invariants (such as face centroid coordinates, surface normals, bounding boxes, or surface areas) as primary identifiers is inherently fragile in parametric CAD. Upstream dimensional edits routinely translate, scale, rotate, or deform geometry. A simple dimensional edit from 10 mm to 50 mm shifts face centroids and changes surface areas, causing pure geometric matching to silently misassociate downstream references or fail during recomputation.

3. **Query-Based References Built from Generation History (`BRepTools_History`) with Fallback Geometric Signatures.** Accepted.
   Each topological entity generated by an operation is addressed through a query-based reference referencing the upstream feature UUID, the topological element type (`face`, `edge`, `vertex`), and the algorithm's generation history path (`generated`, `modified`, `deleted`) tracked via OCCT's `BRepTools_History`. When topology splits (such as a cylindrical face bifurcated by a slot) or history resolution is ambiguous, geometric signatures (surface type, surface normal, centroid, area) serve strictly as deterministic tie-breakers. If a referenced entity is swallowed or eliminated upstream, the reference fails cleanly and reports through `RecomputeFailures` to the Inspector (#34, #170) and agent MCP tools (#153) with interactive re-selection repair. Storing raw face or edge integer indices is strictly forbidden.

## Decision

1. **Reject OCAF `TNaming`.** `made` will not instantiate, link, or depend upon OCCT OCAF document trees (`TDocStd_Document`), OCAF undo managers, or `TNaming_NamedShape` data structures. All document structure remains in Swift's `DocumentModel` and `.made` packages.

2. **Adopt Query-Based Generation History.** Feature sub-element references are expressed as deterministic queries:
   ```
   TopologicalReference = (sourceFeatureId: UUID, elementType: SubelementType, historyPath: [HistoryStep], disambiguator: GeometricSignature?)
   ```
   The kernel service resolves queries during feature replay using `BRepTools_History` records produced by each modeling algorithm (`BRepAlgoAPI_BuilderAlgo`, `BRepFilletAPI_MakeFillet`, `BRepFeat`, etc.). Lineage tracking maps input shapes to their `Generated`, `Modified`, or `Deleted` outcomes at each history step.

3. **Strict Prohibition of Raw Topological Indices.** Storing or passing topological integer indices (e.g., face 0, edge 12) is explicitly prohibited in all persistent schemas, document models, and wire contracts. Sub-elements are addressed exclusively via `TopologicalReference`.

4. **Geometric Signatures as Fallback Disambiguators.** When an upstream operation splits an entity (for example, a through-hole splitting a cylindrical face into two faces, or a boolean cut dividing an edge into two segments), history lineage identifies multiple candidate shapes. In such cases, a secondary `GeometricSignature` acts as a deterministic tie-breaker:
   - **Face signature:** Surface geometry type (plane, cylinder, cone, sphere, torus, b-spline), outward normal at centroid, centroid coordinate, and surface area.
   - **Edge signature:** Curve geometry type (line, circle, ellipse, b-spline), tangent vector at midpoint, midpoint coordinate, and arc length.
   - **Vertex signature:** 3D point coordinate and connected edge count.

5. **Engine-Neutral Wire Representation (Invariant 4).** All naming data structures are declared in `MadeCore/Kernel/Types.swift` as pure Swift `Codable` and `Sendable` types:
   - `TopologicalReference`: The persistent query reference.
   - `SubelementType`: Enum (`face`, `edge`, `vertex`).
   - `HistoryStep`: Lineage query step tracking generation from a source feature.
   - `GeometricSignature`: Value type holding surface/curve invariants for tie-breaking.
   No OCCT C++ types (`TopoDS_Shape`, `BRepTools_History`, `TopExp_Explorer`) cross the kernel boundary into `MadeCore`.

6. **Serialization in `.made` Packages (ADR-D7).** Topological references serialize cleanly into `document.json` within `.made` directory packages as human-readable, Git-friendly JSON objects without proprietary binary blobs.

7. **Graceful Failure and Diagnostics.** When an upstream edit eliminates a referenced topological entity (such as a boss feature being deleted or swallowed by a boolean cut), the query resolution fails cleanly without crashing the kernel service:
   - The kernel returns a typed failure (`KernelErrorCode.topologicalReferenceBroken` / `RecomputeFailures`).
   - The affected feature is flagged with an error state in the Feature Tree (#34, #170).
   - The Inspector highlights the missing reference and prompts the user for interactive re-selection repair.
   - Agent MCP inspection tools (`cad_diagnostics`, #153) return actionable diagnostic envelopes detailing the missing reference and candidate topology.

8. **Clean-Room Swift B-Rep Equivalence.** The clean-room Swift B-rep fallback (#420 to #424) in `libs/` implements identical query semantics and generation history tracking. Swapping the geometry kernel between OCCT and the Swift fallback under Invariant 4 introduces zero changes to document structure or serialized topological references.

## Consequences

- **Parametric Stability:** Upstream parameter edits recompute downstream blends, cuts, and sketches reliably without topological flipping or misassociations.
- **Architectural Cleanliness:** Eliminates the heavyweight OCAF framework, avoiding duplicate document trees, conflicting undo stacks, and C++ memory management overhead.
- **Engine Neutrality (Invariant 4):** Preserves complete isolation of third-party C++ geometry kernel internals from UI, scene models, and agent tools.
- **Process and Thread Safety (Invariants 1 & 7):** Topological queries evaluate asynchronously inside `KernelClient` / `MadeKernelService` without blocking the main UI thread or introducing data races.
- **Human- and Agent-Readable Persistence:** References in `document.json` produce clean, meaningful Git diffs and can be directly inspected and repaired by external AI agents.
